# 数据接口与维护约定

契约定义：`src/domain/types.ts`。静态拓扑：`src/domain/topology.ts`。

## 三层数据

1. **静态 TopologyNode / TopologyEdge**：稳定 ID、设备类别、电压、额定配置、场景位置、支路端点及有功限值。
2. **Snapshot**（schemaVersion 2）：source、timestamp、receivedAt、quality、minute、nodes、edges、alarms、tariff、strategy、metrics。
   - `strategy`：`code`（语言无关的策略代码，如 `absorb`、`peak-discharge`）、`peakLevelMW`、`chargeTargetMWh`、`reserveMWh`、`replanned`。
   - `alarms[]`：`code`（`bess-temp-high` / `bess-overheat-trip`）、`severity`、`nodeId`、`startedAtMinute`。
   - `metrics` 新增 `storedMWh`、`storedDeltaMWh`。
   - 数据层不含任何界面文字；名称、策略说明和告警文本由 `src/i18n.tsx` 按语言翻译。
3. **SimulationDay**：有序 1,440 帧及完成全部积分后的 summary。

`TwinDataSource.loadDay(scenarioId)` 返回 `Promise<SimulationDay>`。已实现 SimulationSource；它是唯一创建/缓存仿真结果的数据适配层。App 支持通过 `source` 参数注入相同契约的数据源，组件不直接调用引擎。

真实接入可实现同样的历史日加载，并实现可选 `subscribe(onSnapshot)`。第一阶段 UI 目前使用 loadDay 回放；持续实时订阅、非剧本时间范围选择和质量状态 UI 尚待真实接入阶段实现，不能仅凭接口存在就称为已接入。

## 电压显示

`TopologyNode.voltage` 是静态交流额定电压等级，不是运行电压遥测。设备列表和详情卡明确显示额定标签；斜线表示设备两侧等级。储能单元及总览使用接入母线的 35 kV 等级，并注明其位于升压后的并网侧，不等同于电池直流或 PCS 端电压。当前 `NodeState` 没有运行电压字段，界面不生成电压波动或把额定值当作测量值。

## 功率符号

- 节点 `injectionMW > 0`：向网络注入；小于零：从网络取电。
- 边 `powerMW > 0`：按静态拓扑 `from → to`；小于零：反向。
- BESS 边方向为 `bus → bess`，所以边正值是充电，节点正值是放电。
- 界面卡片和设备详情显示绝对值 + 方向文字，曲线明确标注“放电为正 / 充电为负”。
- 每个节点满足 `injection + incoming − outgoing = 0`。

支路只提供 `activeUtilizationPct = abs(powerMW) / capacityMW × 100`，称“有功传输占用率”，不是电流或视在功率热负载率。

## SOC 与可用性

`socPct`：全部四台设备按 20 MWh 安装容量加权，故障后仍保留离线电量。

`onlineSocPct`：在线设备按在线容量加权。

`onlinePowerLimitMW`：在线机组额定功率之和，不保证这些功率都能立即输出。

`availableDischargeMW`：当前一分钟内受 SOC 下限、效率及单元额定功率限制后的能力。

## 真实适配器必须补充的校验

- 不直接信任 JSON 的 TypeScript 断言；需验证 schemaVersion、节点/边 ID、有限数值、单位和符号。
- 不使用零填充缺失设备数据。用 quality = missing/stale/disconnected，保留最近有效时间并由 UI 明确展示。
- timestamp 为测量有效时间，receivedAt 为接收时间；对齐时区、乱序与采样步长。
- 校准 AC/DC 计量位置、初末 SOC、费用统计范围及故障状态。
- 不把这里的理想化有功仿真当成现场保护或控制算法。

## 可维护性约束

- domain 和 simulation 禁止依赖 React、Canvas 或帧率。
- 界面禁止修改快照或在 seek 时积分。
- 所有设备/边引用稳定 ID；禁止在模型动画中另写功率或随机数。
- 修改调度规则后运行 Vitest；修改布局/交互后运行相应浏览器测试及生产构建。
- 分钟快照供图表回放，动画的过渡插值不得反向写入业务状态。

## 费用拆解与导出

`simulation/savings.ts` 按 `[0, endMinute)` 计算统一统计窗口；`endMinute = 1440` 使用全天结束状态，否则对应该分钟快照起点。

- `billDifferenceCny`：原始账单差额，即无储能基准电费减当前方案电费。
- `estimatedSavingsCny`：基准未供电量超过引擎数值容差时为 null；详情面板不显示节省率。报告对应字段为 `daySavingsCny`。
- `storedDeltaMWh`：统计期结束时总存量相对 00:00 的变化。
- `offlineStoredMWh`：统计期结束时冻结在离线单元的电量，当前不可调度；不是存量变化的组成量。

故障日首尾电量不要求相同。费用只计算购售电账单，不对期末库存变化进行货币估值。

### 配置与身份

- 使用不可变 `SimulationParameters` 输入替代引擎对全局 CONFIG 的依赖。四个储能单元均分总功率/总容量，三台风机均分总装机；不改变设备 ID。每个方案的节点额定值、线路容量、详情与利用率从同一配置推导。
- 请求携带 `requestId`、参数版本、规范化参数、剧本、负荷/气象数据标识和引擎版本。结果回传同一身份、全日快照、拓扑与求解状态。后到的旧请求不能覆盖新方案；图表、场景、卡片和费用在同一结果提交时一起切换。
- 原方案是用户固定的配置快照，新方案可反复调整；两边共享同一气象、负荷、仿真日期、时间步长、统计区间与费用币种。缓存键包含参数、剧本、输入数据和引擎版本，不能只按 sunny/cloudy/fault 缓存。
- 先记录剖面生成、周期求解、削峰规划、序列化/传输及总耗时，再确定 Worker 和有界缓存策略。拖动合并请求；计算中保留上一份完整结果并明确提示。

光伏交流容量第一版按固定容配比 1.25 推导并显示，DC potential、AC clipping 和网络限发仍分开计算。电价底层仍用 CNY；英文 USD 展示延续已披露的换算，不能把输入币种与内部币种混用。上网电价与谷/平段补电功率默认沿用现有值；是否开放调节需显式决定并披露，调度能力始终受用户设置的总功率、容量及并网限值约束。

显示额定时长 `容量 / 功率`；零功率时显示“不适用”，不除以零。零储能是有效对照组，禁用充放电、无可用电量，SOC 显示不适用。若保留单独的零功率、非零容量配置，其电量只能保持，不能提供供电能力。所有输入必须有限、满足范围与步长；上下限关系、效率及拓扑容量必须验证。

### 周期求解状态

- 每组参数独立求晴天/阴天的周期初态，设置迭代上限和明确的电量收敛容差。结果附 `status`（converged / not-converged / not-applicable）、迭代次数、容差、初末电量、残差及诊断原因；零储能可直接标记不适用。未收敛不能静默展示为已验证的收益结果。
- 故障日从**同一参数配置**下晴天的周期初态开始，记录初始化来源及其收敛状态。故障日自身不强求周期；期末电量变化和离线冻结电量必须保留。
- 未收敛及非周期方案仍可检查物理结果，但费用解释必须标明状态。未供电是合法结果，每一步满足“实际供电 + 未供电 = 需求”与节点功率守恒。

### 对比结果与费用可比性

- 主曲线使用 `storedMWh`；提示里同时显示各自 SOC 和额定容量，零容量 SOC 不适用。当前单方案百分比曲线不作为不同容量的主对比。
- 五项核心结果：电费差额、最大购电 MW、未供电 MWh、弃风弃光 MWh、储存电量 MWh 曲线。最大值、积分与曲线必须使用相同统计窗口；弃风弃光须说明是否含 PV AC clipping，建议默认表示网络限发并单列 clipping。
- 使用显式 `comparisonStatus` / `reason` 与可空的 `comparableSavingsCny`。两方案未供电量差超过已披露容差时，状态为“供电量不同，不可直接比较”，并排列出双方缺电量；原始账单仍可查看，但不能称为节省或显示节省率。
- 即便两方案总缺电量近似相等，也要展示绝对缺电量；不能据此声称可靠性相同或供电完整。若缺电时段不同，要保留对应曲线/诊断。未收敛、故障日非周期库存差异或统计窗口不一致也会限制费用解读。
- 缺电容差及收敛容差是独立、带单位的契约参数，不得由 UI 临时选取。日运行电费对比不包含新增容量投资成本，不等于投资回报分析。

### 验收与后续分享

覆盖默认参数、零储能、零风光、低/零并网限额、大容量、强风光与限发、故障单元、迭代上限触发及连续拖动请求乱序。验证能量和功率守恒、SOC 边界、各侧并网限额、同参数故障初始化、线路占用率与界面一致性、相同输入重复读取一致。

参数分享 URL 后续使用带版本的规范化配置、剧本及查看时刻；两个方案的对比链接需同时保存双方配置。只保存输入而非 1440 帧结果，严格验证范围、长度、版本和未知字段。无效链接不能静默变成另一方案；自定义 CSV 的私有数据不应直接塞入 URL。
