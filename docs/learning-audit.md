## 发现 1：P2 — 手机 L1 高亮目标未进入视口，课程面板遮住部分目标说明

- 位置：`src/ui/learning/useLessonRunner.ts:66` 的高亮逻辑只挂属性，不滚动或检查可见区；`src/ui/learning/lesson-runner.css:113` 将课程固定在手机底部。
- 复现：390×844，页面停在顶部，打开 Learn → L1。第一步让用户观察水箱，但水箱顶部约在 **y=1077 px**，视口高度仅 844 px，可见高度为 0。
- 再将水箱滚动到浏览器认为可见的位置后，水箱范围约 y=226–617，课程面板 y=550–836，底部仍有约 **66 px** 的说明被遮住。继续手动滚动可避开，因此不是无法操作，而是课程没有可靠地展示正在讲解的目标。
- 影响：初学者看不到第一步要求观察的类比，也可能不知道需要先往下滚动；仅有描边不能完成课程引导。
- 漏检原因：`e2e/lessons.spec.ts:142` 检查高亮元素数量、课程退出按钮与面板在视口内、无横向溢出，未断言水箱在可见区域内且未被覆盖。
- 建议：在懒加载目标挂载后，按课程面板的遮挡范围将目标滚到安全可见区域；或者为窄屏课程提供紧凑目标预览。保留手动滚动，避免每帧强行定位。补充首次进入、跨断点缩放、不同语言下的目标可见性断言。
- 证据：[进入时](screenshots/audit-l1-mobile-initial.png)、[滚到目标后](screenshots/audit-l1-mobile-scrolled.png)，坐标在 `learning-audit-evidence.json`。

## 发现 2：P3 — 计算等待被误报为缺少内置仿真数据

- 位置：`src/App.tsx:756`、`:768` 在 busy / error / 非内置数据源时都省略入口回调；`src/ui/learning/LearnHub.tsx:109`、`:131` 将回调缺失统一解释为 `Lessons need the built-in simulation.`。
- 复现：首屏完成后延迟后续 Worker 消息，点击故障日，再打开 Learn。课程和挑战正确禁用，但两处都显示“课程需要内置仿真数据”；实际仍然使用内置引擎，只是计算尚未完成。
- 释放计算消息后按钮恢复可用，说明数据就绪保护本身有效。此问题不造成旧结果答题或错误通关。
- 建议：分别传递内置数据源可用性、计算中、错误状态；等待时显示“正在计算，完成后可开始”，失败时说明失败并提供重试，非内置数据源时才显示当前文案。补充这些状态的中英文验收。
- 证据：[等待中的学习中心](screenshots/audit-pending-hub.png)；原始记录为 `pendingHub.disabled=true`、误导文案数量 2、释放后恢复可用。
