> 目标读者：实现者（Codex）与审核者。本文件定义学习版要新增的全部功能、接入点、数据结构、验收标准和实现顺序。

## 接口核对与实施补充（2026-10-15）

已按 `7d72c12` 核对路径与字段。以下补充优先于原草案中含糊的示例；不改变调度与积分逻辑。

- **阶段 0 状态**：缓存、立即请求、原子提交情景、首次提示布局及矮屏修复已包含在基线提交中。首屏仍不是旧版约 0.5 秒；已有生产预览约 2.2 秒画布可见，首次完整数据约 2.2–5.3 秒。后续以该修复后基线做同环境对照，不把未达成的旧版速度称作已恢复。进入学习版时重跑原有测试，失败必须处理，不能只改超时。
- **三个产品决定**：按原方案替换为“学习”入口；非默认参数开课前说明并确认，保存后恢复；挑战数值通过扫描引擎确定。分阶段本地提交并报告验证结果，未获新的发布要求前不推送。
- **课程上下文**：`Predicate` 和 `Template` 增加第三个数据参数 `context: { sunny: SimulationDay }`（模板语言参数随后），以读取 `StudyResult.sunny`；否则 L5 的函数签名没有晴天对照可用。就绪条件除情景匹配和 `!study.busy` 外，还必须参数键匹配且没有计算错误。保存/恢复包括 original、proposal、情景、时刻、选择、镜头与播放设置，避免故障情景的自动跳转覆盖恢复时刻。课程本身使用独立运行状态，不借用模态 `lesson` 值来暂停场景。
- **预测答案**：允许多个数据谓词同时成立，选项文案不能暗示互斥；默认课例仍通过测试确认预期答案。所有复合数值和峰值时刻引用当前结果。L2 10:00 吸纳、L3 19:00 放电、L4 阴天 03:00 谷充以及 L5 同时刻晴天对照已用引擎核验。
- **水箱比例**：使用同一组固定视觉标尺或显式传入 scaleCapacityMWh / scaleRatedMW，不可每次以新方案自身作分母。否则容量翻倍后水箱宽度不变。参数草稿没有对应电量时，明确标“容量预览”，不冒用旧结果电量或显示为实时水位。
- **挑战费用口径**：C3 的“储能节省”使用新方案当天 `savingsBreakdown(day, 1440)` 的同电价无储能基准；不能直接用不同电价的 original/proposal 账单差来当储能收益。目标值由扫描确定。价差计分改为允许派生评分 `peakPrice - valleyPrice`，不假装它是已有 ParameterKey。可靠性关卡 C1/C2 允许起始与通关供电量不同（这正是目标），只拒绝未收敛；“供电量不同不可比较”只用于收益判定，不可禁止可靠性改善通关。
- **能量统计边界**：采用半开区间 `[startMinute, endMinute)`，全天 `[0, 1440)`，截至 12:00 为 `[0, 720)`，与现有 `savingsBreakdown` 相同。储能损耗必须使用窗口始末直流库存变化，而不是直接把充入量减放出量。风光源使用已扣弃电的 `metrics.pvMW / windMW`，负荷汇为 `servedMW`，未供电单列。流向是约定的归因分配，不是实际电子来源追踪。
- **测试与提交**：每阶段跑全部单元测试、构建和完整浏览器回归；新增用例先单独调通。每一步提交后给审核者提供结果；可选 P2 单独实施。术语阶段先在“关于模型”中提供完整列表入口，第 4 步再统一收入学习中心，不提前加入未完成的入口。

## 0. 定位与总原则

**定位**：个人作品集 + 初学者入门。让没有电力背景的人在 10 分钟内看懂：储能为什么充、什么时候放、容量和功率有什么区别、它怎么帮人省钱和保供电。

**总原则（所有功能都必须遵守）**

1. **学习层只读，不改物理。** 新功能放在 `src/learning/`（数据与纯函数）和 `src/ui/learning/`（组件）。不得修改 `src/simulation/engine.ts` 的调度与积分逻辑；只能读取 `Snapshot`、`SimulationDay`、`StudyResult`。如确需新的派生量，写成 `src/simulation/` 或 `src/learning/` 下的纯函数并配单元测试。
2. **数值永远来自仿真，不写死在文案里。** 课程、挑战、提示中出现的数字（MW、MWh、时刻、金额）必须通过模板从当前数据计算得到。答案判定也必须基于数据谓词，而不是硬编码“正确选项是 B”。
3. **中英文同时交付。** 所有界面文字进入 `src/i18n.tsx` 的 `zh` 与 `en`，或新建 `src/learning/copy.ts`，并用 TypeScript 类型约束两种语言结构一致（参考 `src/explorerCopyZh.ts` 对 `CabinetCopy` 的做法）。
4. **演示标识保持明确。** 类比、动画速度、示意流向都要标注“示意”，不得让人误以为是实测。
5. **可访问性。** 键盘可达、焦点管理正确、`prefers-reduced-motion` 下停止循环动画但保留静态信息，手机（390 px）可用，无横向滚动。
6. **性能预算。** 学习层代码按需懒加载（`lazy()`），首屏 JS 增量 ≤ 15 KB gzip；不新增运行时依赖（桑基图使用已有的 `recharts` `Sankey`）。首屏和切换情景的耗时不得比基线变差。
7. **不新增“假控制”。** 不出现任何看起来能远程控制设备的按钮。

### 0.1 前置条件

开始本规格前，必须先修完当前已知问题并提交：

- 首屏与切换情景变慢（生产构建实测首屏 2.5–3.1 s，切换 1.6–5.7 s；基线约 0.5 s）。

- 1366 宽度下顶栏 “Guided tour” 折成两行（见 §1.3，本规格会顺带解决）。

## 2. 水箱类比（Storage tank analogy）

### 2.1 目的

讲清 **功率（MW）≠ 容量（MWh）**，这是初学者最常见的困惑。

| 概念            | 类比                             |
| --------------- | -------------------------------- |
| 容量 MWh        | 水箱大小                         |
| 功率 MW         | 水管粗细（每小时最多进出多少水） |
| SOC / 储存电量  | 水位                             |
| 时长 = MWh ÷ MW | 用最粗的水管放空一整箱要几小时   |
| SOC 上下限      | 水箱上下两条“不能越过”的警戒线   |
| 充放电效率      | 管道漏掉的一小部分水             |

### 2.2 组件

`src/ui/learning/StorageTank.tsx`（SVG），属性：

```ts
interface StorageTankProps {
  capacityMWh: number // 安装容量；0 表示没有水箱
  ratedMW: number // 额定功率；0 表示水管关闭
  storedMWh: number // 当前储存电量（DC 侧，与 metrics.storedMWh 一致）
  socMinPct: number
  socMaxPct: number
  flowMW: number // >0 放电，<0 充电，0 静止（与 batteryDischargeMW - batteryChargeMW 一致）
  compareTo?: { capacityMWh: number; ratedMW: number } // 方案对比时显示原方案虚线轮廓
  size?: 'sm' | 'md'
}
```

绘制规则：

- 水箱高度固定；**宽度** ∝ `capacityMWh`，按当前页面中最大值归一化，最小宽度保证可读。
- 水管 **粗细** ∝ `ratedMW`。
- 水位 = `storedMWh / capacityMWh`。
- SOC 上下限画成两条虚线，旁边标注 “可用区间”。
- 水流动画方向：充电向内、放电向外；流速 ∝ `|flowMW| / ratedMW`；文字标注“示意”。
- 下方一行算式，数值由模板生成：`{capacity} MWh ÷ {rated} MW = {hours} 小时`。
- 边界状态：
  - `capacityMWh = 0`：显示 “没有储能水箱”，不画水位；
  - `ratedMW = 0`：水管画成关闭状态，算式显示 “无法充放电”；
  - 两者都为 0：只显示一句说明。

实现补充（第 2 步）：`StorageTankProps` 使用判别联合。快照模式传入 `storedMWh` 和 `flowMW`；草稿模式传 `preview: true`，类型上禁止同时传入这两项，避免显示旧数据。草稿斜线带仅表示 SOC 可用区间。固定视觉标尺读取参数规则上限（80 MWh、20 MW），极小尺寸保留最小可见值。`LazyStorageTank` 负责按需加载，纯计算位于 `src/learning/tank.ts`。水面和虚线动画只表达方向与相对速度，不积分电量；暂停按钮与减少动态效果设置均可停止循环，静态箭头和读数保留。时长按全部铭牌容量计算，额定管径不表示故障后的可用功率。

### 2.3 接入点

1. **储能总览详情卡**（`DetailCard.tsx`，`selection === 'bess-cluster'`）：放在 SOC 环下方，读取当前快照，随时间轴实时变化。
2. **参数面板**（`DesignStudy.tsx`，“新方案” 摘要卡）：拖动功率和容量滑块时立即变化，不等后台计算完成（只依赖参数）；`compareTo` 显示原方案轮廓。
3. **课程 L1**（§4）。

### 2.4 验收

- 单元测试：时长、水位比例、边界状态的计算函数（抽成 `src/learning/tank.ts` 纯函数）。
- 浏览器测试：在参数面板把容量从 20 改到 40，水箱宽度变大、水管不变；把功率改为 0，显示 “无法充放电”。
- 减少动态效果模式下没有循环动画，水位与箭头仍可见。

## 3. 术语提示（Glossary）

### 3.1 数据

```ts
export interface GlossaryEntry {
  id: GlossaryId
```

首批术语（至少 20 个）：SOC、SOH、MW、MWh、时长、PCS、BMS、EMS、并网点 / 购电上限、削峰、峰谷套利、谷 / 平 / 峰电价、弃风弃光、逆变器削顶、充放电效率、周期稳态、未供电量、电芯、模组、电池簇、额定电压、直流 / 交流。

### 3.2 组件

`<Term id="soc">SOC</Term>`（`src/ui/learning/Term.tsx`）：

- 渲染为带虚线下划线的 `button`，点击或聚焦后弹出小卡片（不要使用 `title` 属性，触屏上不可用）。

### 3.3 使用范围（避免满屏下划线）

- 每张卡片、每个面板中，同一术语只标注第一次出现。
- 必须覆盖：KPI 的 “SOC”、时间轴的策略名、储能详情卡的 SOH / 可用放电能力、电压说明中的 PCS、参数面板中所有参数标签、电费说明中的谷 / 平 / 峰。
- 探索器内部不加（探索器已有自己的部件说明）。

### 3.4 验收

- 单元测试：每个 `GlossaryId` 都有中英文 `term` 和 `short`；`related` 引用都存在；没有重复 id。
- 浏览器测试：键盘 Tab 到 “SOC” 按 Enter 打开，Esc 关闭后焦点回到原位；术语表搜索 “削峰” 能找到。

## 4. 课程：先预测，再揭晓（Lessons）

### 4.1 目的

在关键时刻暂停，先让用户猜，再播放结果并解释原因。

### 4.2 数据结构

`src/learning/lessons.ts`：

```ts
type Predicate = (s: Snapshot, day: SimulationDay) => boolean
type Template = (s: Snapshot, day: SimulationDay, lang: Lang) => string

interface LessonStep {
  id: string
  minute: number // 本步要停在的时刻
  playFrom?: number // 若设置，从该时刻播放到 minute（演示过程）
  focus?: Selection | 'overview' // 镜头
  highlight?: string // 高亮的界面元素 CSS 选择器
  title: Localized
  body: Template // 说明文字，数值来自数据
  predict?: {
    question: Localized
    options: { id: string; label: Localized; correct: Predicate }[] // 用数据判定哪个选项成立
    revealAt: number // 用户作答后播放到这个时刻再揭晓
    explain: Template // 揭晓说明，引用真实数值
  }
}
interface Lesson {
  id: 'l1-basics' | 'l2-solar' | 'l3-peak' | 'l4-cloudy' | 'l5-fault'
  scenario: ScenarioId
  title: Localized
  summary: Localized
  steps: LessonStep[]
}
```

**判定规则**：揭晓时，用 `revealAt` 时刻的快照逐个执行 `options[].correct`，至少一个为真才算题目有效。如果没有选项成立（例如用户改了参数导致行为变化），显示 “这组参数下情况不同” 并给出实际数值，而不是报错。

### 4.3 课程内容（默认参数下）

| 课程          | 情景   | 关键时刻      | 预测问题                                                                            | 判定依据                                                                       |
| ------------- | ------ | ------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| L1 储能是什么 | 晴天   | 12:00         | 无提问；展示水箱类比、MW 与 MWh 的区别                                              | —                                                                              |

## 5. 挑战关卡（Challenges）

### 5.1 目的

把参数面板变成有目标的小游戏，让用户动手发现规律。

### 5.2 数据结构

`src/learning/challenges.ts`：

```ts
interface Criterion {
  id: string
  label: Localized
  test: (r: StudyResult) => { pass: boolean; value: string } // value 用于显示当前数值
}
interface Challenge {
  id: 'c1-cloudy-supply' | 'c2-import-cap' | 'c3-spread' | 'c4-curtailment'
  scenario: ScenarioId
  start: Partial<SimulationParameters> // 起始参数（在默认参数基础上打补丁）
  editable: ParameterKey[] // 只开放这些滑块，其他锁定并显示锁图标
  criteria: Criterion[] // 全部满足即通关
  score?: { key: ParameterKey; better: 'lower' | 'higher'; stars: [number, number, number] }
  hint: Localized
  explain: Localized // 通关后解释背后的道理
}
```

### 5.3 关卡内容

| 关卡            | 情景与起始条件                                                 | 可调参数             | 通关条件                                    | 计分           | 想讲清的道理                   |
| --------------- | -------------------------------------------------------------- | -------------------- | ------------------------------------------- | -------------- | ------------------------------ |
| C1 阴天不缺电   | 阴天，购电上限调低（数值由实现者用引擎确定，要求起始状态缺电） | 储能容量、储能功率   | 未供电量 ≤ 0.001 MWh，且求解收敛            | 容量越小星越多 | 容量要够撑过晚高峰             |
| C2 压住购电上限 | 晴天，购电上限 8 MW                                            | 储能容量、储能功率   | 未供电量 ≤ 0.001 MWh                        | 功率越小越好   | 购电上限决定储能必须补多少功率 |
| C3 峰谷价差     | 晴天，默认储能                                                 | 谷时、平时、峰时电价 | 全天可比节省 ≥ 目标值（由实现者用引擎确定） | 价差越小越好   | 峰谷价差越大，套利越赚钱       |
| C4 风光过剩     | 晴天，光伏、风电装机大幅提高，上网上限为 0                     | 储能容量、储能功率   | 弃风弃光 ≤ 目标值                           | 容量越小越好   | 储能可以减少浪费的清洁电       |

**数值确定方法**：实现者必须写一个脚本或测试，用 `createSimulationEngine` 扫描参数，确定每关的起始值、目标值和三档星级阈值，并满足：

1. 起始参数 **不通关**；
2. 至少存在一组可调参数 **能通关**；
3. 三星阈值可达，一星阈值比较宽松；
4. 所有阈值写进 `challenges.ts`，并在单元测试里重新验证 1–3。

### 5.4 运行方式

- 复用 `DesignStudy` 与 `useDesignStudy`，新增 `mode: 'free' | { challenge: ChallengeId }`：
  - 挑战模式下，不可调参数的滑块禁用并显示锁图标；
  - “原方案” 固定为关卡起始参数；
  - 顶部显示目标清单，每条通过 / 未通过实时更新，并显示当前数值；
  - 后台计算未完成时，目标清单显示 “计算中”，不得用旧结果判定。
- 通关后显示星级、解释和 “下一关”；进度写入 `progress.ts`。
- 退出挑战时恢复用户原来的自由模式参数。

### 5.5 验收

- 单元测试：§5.3 的 4 条要求对每关成立；`criteria` 在不收敛或供电量不同的结果上不会误判为通过。
- 浏览器测试：C1 从起始状态调大容量直到通关，星级正确显示；快速拖动滑块时，目标清单只反映最新一次完整结果。

## 6. 一天能量去向图（Energy flows / Sankey）

### 6.1 目的

用流向宽度展示 “电从哪来、到哪去”，作为一天的总结。

### 6.2 计算（纯函数，带测试）

`src/simulation/energyFlows.ts`：

```ts
interface EnergyFlows {
  sources: { pv: number; wind: number; gridImport: number; batteryDischarge: number } // MWh
  sinks: { load: number; batteryCharge: number; gridExport: number } // MWh
  flows: { from: SourceKey; to: SinkKey; mwh: number }[]
  lost: { curtailed: number; clipping: number; unserved: number } // 单独列出
}
export function energyFlows(day: SimulationDay, startMinute: number, endMinute: number): EnergyFlows
```

**每分钟的分配规则**（必须写进注释和 `docs/simulation.md`）：

1. 风光（`renewableMW`，已扣除弃电）先供负荷，余量给储能充电，再余量上网；
2. 储能放电只供负荷（当前调度不会放电上网；若出现，按比例计入上网并在测试中报告）；
3. 购电补足剩余负荷，再余量给储能充电（谷时、平段补电）；
4. 每分钟检查 `Σsources = Σsinks`，误差 ≤ 1e-6 MW。

风光内部的光伏与风电按各自出力比例拆分。弃风弃光、逆变器削顶、未供电量不参与平衡，作为 “损失 / 缺口” 单独展示。

### 6.3 展示

- 新组件 `src/ui/learning/EnergyFlowChart.tsx`，使用 `recharts` 的 `Sankey`，颜色沿用 `TONE`（风光绿、电网蓝、充电青、放电橙）。
- 入口：
  - 时间轴播放到 23:59 时，弹出非阻塞提示 “看看今天的能量去向”；
  - 学习面板、电费说明面板中各放一个入口。
- 支持 “全天 / 截至当前” 切换（与 `SavingsPanel` 一致）。
- 提供同数据的表格版本（可展开），供屏幕阅读器和不擅长看图的用户使用。
- 值为 0 的流向不画；储能损耗（充入电量 − 放出电量 − 储存变化）在表格中注明。

实现补充（第 3 步）：汇总接口增加 `storage`（期初、期末、变化、转换损耗）与 `diagnostics`（最大分钟平衡差、储能上网量）。来源归因逐分钟执行：风光先负荷再充电，储能再负荷，购电补负荷与充电，剩余各来源按剩余功率占比分配上网。当天播放到 23:59 后只提示一次，不自动打开或夺取焦点；关闭图表保留原费用面板及范围。学习中心还未实施，先在关于模型提供补充入口，第 4 步再统一接入。

### 6.4 验收

- 单元测试：三个情景、多个时间窗口下，`flows` 之和与 `sources`、`sinks` 都一致；与 `day.summary` 的 `importMWh`、`exportMWh` 一致；零储能参数下没有储能节点。
- 浏览器测试：晴天全天图中存在 “光伏 → 储能” 和 “储能 → 负荷” 两条流向；切换 “截至 12:00” 后 “储能 → 负荷” 消失。
